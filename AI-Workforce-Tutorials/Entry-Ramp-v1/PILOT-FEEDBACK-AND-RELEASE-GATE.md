# Entry Ramp v1 — Pilot Feedback and Release Gate

## Status definitions

- **Functional acceptance:** a clean-profile/fresh-workspace validation passes M0, M0.5 Gate A, Conductor authentication and Gate B, M1 workshop, M1 practice-run, and the cohort-one action boundary using published `main` materials.
- **Field acceptance:** representative learners complete the actual Windows Hermes Desktop path with only normal facilitator support, and pilot evidence shows that instructions, approval boundaries, and artifacts are understandable.

Entry Ramp v1 is functionally accepted at Conductor distribution v0.1.1. It is not field-accepted until this pilot gate is met.

## Pilot design

Run a facilitated pilot with **3–5 learners** who vary in technical comfort and selected workflow. Include at least one operational workflow, such as client-intake drafting or project-status preparation, and at least one knowledge-work workflow.

Use the exact published `main` repository and Conductor distribution version being tested. Do not mix unpublished facilitator changes into the pilot.

## Facilitator observation record

For each learner, record only:

1. **Setup stall:** the first point at which the learner needed non-routine intervention.
2. **Instruction ambiguity:** wording/path/expectation that caused confusion.
3. **Approval-boundary explanation:** whether the learner independently distinguished draft/proposal work from prohibited cohort-one external execution.

Do not capture passwords, API keys, full confidential inputs, or unnecessary personal data.

## Field-acceptance release gate

Entry Ramp v1 becomes **field-accepted** only when all conditions hold:

- [ ] At least 3 pilot learners complete the journey using the published materials.
- [ ] At least one knowledge-work and one operational workflow are represented.
- [ ] Every learner either completes all evidence gates or has a documented blocker and recovery/catch-up path.
- [ ] No pilot requires an undocumented facilitator workaround to complete a stated gate.
- [ ] Every learner can state the cohort-one human approval boundary in their own words.
- [ ] No live external execution, credential collection in course artifacts/chat, or unauthorized file scope occurs.
- [ ] Pilot findings are triaged into: correct now / clarify before next cohort / advanced-topic backlog.
- [ ] A human course owner approves the pilot release decision and records the rationale.
