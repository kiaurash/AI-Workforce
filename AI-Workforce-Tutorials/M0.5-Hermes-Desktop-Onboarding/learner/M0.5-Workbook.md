# Gate B — Conductor Distribution Readiness

## B1. Import the course Conductor profile

The distribution installs **one Conductor profile**, not a complete workforce. It does not carry your credentials, sessions, or private memory.

1. Follow the [AI Workforce Conductor distribution instructions](../../../hermes-profiles/ai-workforce-conductor/README.md).

3. Open its canonical Bot Chat.
4. Keep this repository open as the project workspace.

## B1.5. Configure and verify the imported Conductor

A profile distribution intentionally excludes credentials and may not carry a usable model configuration. While the **AI Workforce Conductor** profile is selected, complete your own local provider/model sign-in or configuration in Hermes Desktop. Do not enter credentials into course files or chat.

Send one harmless ordinary message in the Conductor's canonical Bot Chat and confirm it receives a response. If it cannot dispatch, resolve this model/provider setup blocker before attempting the safe-stop test.

- [ ] Conductor provider/model access is configured locally.

## Boundaries to retain

- A profile appearing in the Bots tab is **configuration**, not demonstrated capability; activation requires a passed role-specific test and a recorded human decision.
- Bot messages are asynchronous coordination signals. Saved repository artifacts—not chat assertions—are authoritative.
- A fresh profile or subagent conversation is not automatically a filesystem, credential, or tool-permission boundary.
- Do not enable external actions, add credentials, or activate Builder/Reviewer/Observer roles merely to finish M0.5.
